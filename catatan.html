Catatan UTS PDM

Baca dari atas ke bawah sekali, terus pas di ruang ujian buka bagian kamus english sama ceklis aja.

Cara pakai: soal UTS lu bahasa Inggris, dan masalahnya biasanya bukan gak bisa jawab — tapi gak tau yang diminta apaan.
  1. Peta soal — tebak dulu ini nomor tipe apa, biar tau harus nulis apa.
  2. Kamus english — tiap perintah soal diterjemahin + yang harus lu tulis.
  3. Template — bentuk jawaban siap contekin, tinggal ganti isi.
  4. Ceklis — 3 menit terakhir sebelum kumpul.
1

Peta soal: kenali tipe dulu

5 detik pertama, tentuin ini nomor apa

Sebelum nulis apa pun, cari kata kunci di soalnya. Tiap tipe punya bentuk jawaban beda, dan lu gak perlu mikir lagi setelah tau tipenya.

kata kunci di soaltipe soalbobot biasanya
IPO, input/output, specificationdesain data12–15 poin
trace, desk check, show valuetracing6–8 poin
identify the errors, correctkoreksi kode5–6 poin

urutan ngerjain yang paling untung Kerjain IPO → test case → hitungan → koreksi error → trace → pseudokode. Pseudokode terakhir, karena bobotnya gede tapi paling makan waktu. Kalau waktu habis di pseudokode, poin IPO yang gampang udah aman duluan.
2

Kamus perintah soal

English → artinya → yang harus lu tulis

Ini bagian yang lu bilang bikin bingung. Kalau ketemu kalimat kayak gini, langsung liat baris tulis apa-nya.

"Define the IPO model" / "Write the IPO chart"

bikin model Input–Process–Output

Tulis: 3 baris, isinya nama variabel, bukan kalimat panjang. INPUT / PROCESS / OUTPUT.

"Declare all variables with appropriate data types"

deklarasikan semua variabel + tipe datanya yang pas

Tulis: satu baris DECLARE Tipe nama per variabel. Konstanta pakai DECLARE GLOBAL CONSTANT + tanda =. Jangan ada rumus di baris ini.

"Identify the two errors and write the corrected code"

temuin 2 kesalahan, terus tulis versi benernya

Tulis: format nomor — 1. Baris 06: ... seharusnya ... lalu alasannya satu kalimat. Habis itu tulis ulang kode lengkap yang udah bener. Dua-duanya diminta, jangan cuma salah satunya.

"Trace the following algorithm" / "Perform a desk check"

jalanin kodenya manual, catat tiap perubahan nilai

Tulis: tabel. Kolom = tiap variabel yang berubah + satu kolom output. Satu baris per baris kode yang jalan. Baris terakhir = output.

"State the output" / "What is displayed on the screen?"

hasil yang muncul di layar apa

Tulis: angkanya aja, tapi tetep sertakan tabelnya kalau soalnya minta trace. Kalau cuma "state the output" tanpa minta trace, boleh langsung jawab — tapi tambah 1 baris cara dapetnya.

"Provide three test cases that produce different outcomes"

kasih 3 data uji yang hasilnya beda-beda

Tulis: 3 baris, tiap baris isi semua field input → hasil yang diharapkan. Wajib ada yang diterima dan yang ditolak.

"Write the pseudocode" / "Design the algorithm"

tulis algoritmanya dalam pseudokode

Tulis: kerangka MODULE Main() ... END MODULE dulu, baru isi. Tiap IF wajib ada END IF, tiap WHILE wajib ada END WHILE.

"Explain why ..." / "Justify your answer" / "Give a reason"

jelasin alasannya

Tulis: 1–2 kalimat, pola: karena [fakta di kode] maka [akibatnya]. Jangan cuma ngulang pertanyaan.

"Is a FOR loop allowed here? Explain."

boleh gak pakai FOR di kasus ini

Tulis: jawaban ya/tidak dulu, baru alasannya. Contoh: "Ya, boleh, karena jumlah putarannya sudah diketahui (4 kali). FOR dipakai kalau batasnya pasti, WHILE kalau berhentinya tergantung kondisi."

"Why is studentID not an Integer?"

kenapa NIM gak boleh Integer

Tulis: "Karena NIM tidak dihitung, cuma disimpan dan ditampilkan. Kalau Integer, angka 0 di depan hilang dan NIM gak bisa mengandung huruf."

"Differentiate between variable and constant"

beda variabel sama konstanta

Tulis: "Variabel nilainya bisa berubah selama program jalan. Konstanta nilainya tetap dan gak bisa diubah, ditulis sekali di awal."

"What is a sentinel value?" / "sentinel-controlled loop"

nilai sentinel / loop berhenti pakai penanda

Tulis: "Nilai khusus yang jadi tanda berhenti, misalnya -1. Loop jalan terus sampai user memasukkan nilai itu. Beda dengan counter loop yang jumlahnya udah pasti."

"Calculate the total cost" / "Determine the final price"

hitung totalnya

Tulis: rumusnya dulu, baru angkanya. (4 × 3000) + 10000 − 2000 = 20000. Jangan langsung hasil akhir — poinnya di langkah.

hati-hati kata-kata jebakan "assume all variables are declared" → lu gak perlu nulis DECLARE, langsung ke proses.
"based on the code above" → jangan benerin dulu, trace apa adanya (walaupun salah).
"after correction" → baru pakai versi yang udah dibenerin.
"state" = tulis hasilnya aja. "show" / "justify" = harus ada langkahnya.

Kalau soalnya begini, jawabnya begini

contoh soal → jawaban jadi

A Soal spesifikasi data (pasti keluar)

Soalnya: "A campus vending machine needs a program. Users enter studentID, productCode, and quantity. Define the IPO model, declare six variables, and provide three test cases."

Yang lu tulis:

(a) IPO
INPUT   : studentID, productCode, quantity
PROCESS : validasi 1 <= quantity <= 5
          cek stok productCode
          hitung totalPrice = quantity * productPrice
OUTPUT  : receiptMessage, totalPrice

(b) Deklarasi
DECLARE GLOBAL CONSTANT Integer PRICE_PER_ITEM = 5000
DECLARE String  studentID
DECLARE String  productCode
DECLARE String  receiptMessage
DECLARE Integer quantity
DECLARE Integer totalPrice

(c) Test case
"260199", "A01", 2  -> diterima, total 10000
"260199", "A01", 5  -> diterima, total 25000
"260199", "A01", 9  -> ditolak, quantity di luar 1-5

Perhatiin: test case-nya selalu ada satu yang ditolak. Itu yang dikasih poin.

B Soal trace + cari error

Soalnya: "Trace the program and write the output. Identify the two errors."

Yang lu tulis: tabel dulu, baru daftar error.

Tabel trace (nilai = setelah baris selesai)
baris | round | score | total | output
04-05 |   1   |   -   |  10   |   -
07-09 |   2   |  15   |  25   |   -
07-09 |   3   |  20   |  45   |   -
  06  |   3   |   -   |  45   | 3 < 3 FALSE, stop
  11  |   -   |   -   |  45   |  45

Output: 45

Error 1: baris 06 `WHILE round < 3` seharusnya `WHILE round <= 3`.
         Akibatnya loop cuma jalan 2 kali, input ketiga tidak dibaca.
Error 2: baris 08 `SET total = score` seharusnya `SET total = total + score`.
         Akibatnya nilai lama tertimpa, bukan dijumlah.

C Soal nulis pseudokode dari cerita

Soalnya: "Write the pseudocode for the following rules."

Yang lu tulis: kerangka dulu, baru isi per aturan.

MODULE Main()
    INPUT patientType, age, isUrgent

    IF patientType = "BPJS" THEN
        SET consultFee = 0
    ELSE
        IF age >= 60 THEN
            SET consultFee = BASE_FEE / 2
        ELSE
            SET consultFee = BASE_FEE
        END IF
    END IF

    SET totalBill = consultFee

    IF isUrgent = TRUE THEN
        SET totalBill = totalBill + URGENT_FEE
    END IF

    DISPLAY patientType, consultFee, totalBill
END MODULE

bentuknya hafalin, isinya ganti

1 Blok IPO

INPUT   : a, b, c
PROCESS : validasi ...
          hitung ...
OUTPUT  : x, y

2 Blok deklarasi

DECLARE GLOBAL CONSTANT Integer NAMA_KONSTANTA = nilai

DECLARE String  namaVariabel
DECLARE Integer namaVariabel
DECLARE Real    namaVariabel
DECLARE Boolean namaVariabel

Urutan: konstanta dulu, baru variabel. Satu variabel satu baris. Gak ada tanda = di variabel biasa.

    DISPLAY ...
END MODULE

6 Format jawab "cari error"

Error 1: baris XX `kode salah` seharusnya `kode benar`.
         Akibatnya ...

Poin "akibatnya" itu yang bedain nilai penuh sama setengah. Jangan skip.

Tipe data: tabel keputusan

lihat kata bendanya, bukan nama variabelnya

kalau isinya ...tipenya
nama, NIM, kode, pesan, status teksString
jumlah, umur, jam, kuantitas, hitungan bulatInteger
berat, suhu, harga desimal, hasil bagiReal
TRUE / FALSE, ya / tidak, member / bukanBoolean
tarif, potongan, deposit (tetap)GLOBAL CONSTANT Integer
trik cepat Ada tanda kutip di contoh datanya ("A01") → String. Ada titik desimal (3.5) → Real. Isinya cuma TRUE/FALSE → Boolean. Sisanya → Integer.
jangan ketuker estimatedDays isinya 1 atau 2 → Integer. Tapi kalau mau ditampilin "1 Hari", ya jadi String — pilih satu, jangan campur. Yang penting konsisten sama isi yang lu simpan.
6

Enam pola pseudokode

90% soal cuma butuh ini

1 IF / ELSE — dua kemungkinan

IF kondisi THEN
    SET x = nilaiA
ELSE
    SET x = nilaiB
END IF

2 IF / ELSE IF / ELSE — tiga kemungkinan atau lebih

IF nilai >= 85 THEN
    SET grade = "A"
ELSE IF nilai >= 70 THEN
    SET grade = "B"
ELSE
    SET grade = "C"
END IF

Pakai ini kalau cuma satu cabang yang boleh jalan. Contoh salah: dua IF terpisah untuk nilai > 90 dan nilai > 80 — nilai 95 kena dua-duanya.

3 Dua IF terpisah — dua-duanya boleh kejadian

IF isMember = TRUE THEN
    SET discount = 2000
END IF

IF isUrgent = TRUE THEN
    SET extraFee = 25000
END IF

Pakai ini kalau aturannya berdiri sendiri, misalnya soal nulis "berlaku untuk semua pasien".

4 WHILE pakai counter — jumlah putaran pasti

SET count = 1
WHILE count <= 4 DO
    INPUT nilai
    SET total = total + nilai
    SET count = count + 1
END WHILE

Kalau mau 4 putaran, kondisinya <= 4, bukan < 4. Ini kesalahan nomor satu di soal tracing.

5 WHILE pakai sentinel — berhenti kalau ada penanda

INPUT nilai
WHILE nilai <> -1 DO
    SET total = total + nilai
    SET count = count + 1
    INPUT nilai
END WHILE

INPUT-nya dua kali: sekali sebelum loop, sekali di akhir dalam loop. Kalau cuma satu, loop-nya jalan terus.

6 MODULE dengan parameter (dan REF)

MODULE Hit(Integer a, Integer REF b)
    SET a = a + 4
    SET b = b - a
    DISPLAY a, b
END MODULE

MODULE Main()
    SET m = 6
    SET n = 9
    Hit(m, n)
    DISPLAY m, n
END MODULE

Tanpa REF = fotokopi, nilai asli di Main gak berubah. Pakai REF = alamat asli, nilai di Main ikut berubah. Yang ada kata REF itu yang tembus balik.

7

Trace: 6 aturan yang gak boleh dilanggar

bobot 6 poin, gampang hilang gara-gara format

  • Satu baris tabel = satu baris kode yang jalan. Baris yang sebaris (misal 07–09) digabung jadi satu baris tabel.
  • Nilai ditulis SETELAH baris itu selesai. Jangan campur: satu kolom pakai nilai sebelum, kolom lain sesudah.
  • Satu putaran loop = satu baris. Empat putaran ya empat baris.
  • Baris kondisi yang FALSE wajib ditulis, plus tulisan stop. Ini yang nunjukin lu paham kenapa loop berhenti.
  • Baris DISPLAY paling bawah, isi kolom output. Itu jawaban "state the output".
  • Kolom = variabel yang berubah aja, plus satu kolom output. Jangan semua variabel dimasukin.
cek cepat Kalau hasil bagi lu aneh (misal rata-rata 6.5 dari data 20–30), berarti ada bug — bukan salah hitung. Trace apa adanya dulu, jangan dibenerin sendiri kecuali diminta.

Ceklis 3 menit terakhir

sebelum kumpul, jalanin ini

  • Tiap IF ada END IF-nya? Hitung jumlahnya, harus sama.
  • Tiap WHILE ada END WHILE-nya?
  • Konstanta udah pakai GLOBAL CONSTANT dan ada tanda =?
  • Semua variabel yang dipakai udah dideklarasi? Gak ada yang tiba-tiba muncul.
  • Tabel trace ada baris stop dan baris output?
  • Test case ada yang ditolak? Kalau semua diterima, kurang satu.
  • Bagian "identify the errors" ada dua error? Bukan satu.
  • Angka akhir udah dicek ulang? Kalau hasilnya aneh, cek tanda + / − / kurung.
  • Nama variabel sama persis kayak di soal? Jangan diganti sendiri.
yang gak boleh lu lakuin Nulis pseudokode dari atas ke bawah sambil mikir. Tulis MODULE dan END MODULE dulu, kosongin isinya, baru diisi per aturan. Kalau nulis lurus, END IF hampir pasti kelupaan.
