Spesifikasi & Desain Data 15 poin

IPO tiga baris + deklarasi variabel
Contoh soal Study pod reservation. Input memberID, startHour, visitorCount, pod availability. Validasi 8 ≤ startHour ≤ 19 dan 1 ≤ visitorCount ≤ 3, cek pod kosong, bikin reservationCode. Output: status diterima/ditolak, kode konfirmasi.
Cara ngerjain
1
Garisi kata benda datanya. "memberID", "startHour", "jumlah pengunjung" → itu calon INPUT. Jangan ngarang input yang nggak disebut.
2
Kalimat syarat = PROCESS. "between 8 and 19", "max 3 people", "must be available" → tulis jadi aturan validasi, bukan cerita.
3
Output = yang dilihat user. Status + kode konfirmasi. Bukan "menyimpan ke database".
4
Tulis 3 baris label INPUT / PROCESS / OUTPUT. Satu baris satu peran, jangan dicampur.
5
Deklarasi satu-satu: DECLARE <Tipe> <nama>. ID → String. Jam / jumlah → Integer. Status → Boolean. Pesan → String.
6
Tulis alasannya satu kalimat. "ID itu identifier, bukan kuantitas — '00123' harus tetap 5 karakter." Ini yang dikasih poin penalaran.
Jawaban model
INPUT   memberID, startHour, visitorCount, podAvailable
PROCESS validasi 8 <= startHour <= 19
        validasi 1 <= visitorCount <= 3
        IF podAvailable = TRUE THEN buat reservationCode
OUTPUT  status diterima / ditolak, confirmationMessage, reservationCode

DECLARE String  memberID
DECLARE Integer startHour
DECLARE Integer visitorCount
DECLARE Boolean podAvailable
DECLARE String  reservationCode
DECLARE String  confirmationMessage
Poin gampang hilang: nulis DECLARE memberID String (kebalik), atau ID dijadikan Integer.
Sekarang lu coba · soal 1

Gym locker booking. Datanya: lockerCode (contoh "0071"), hoursUsed, isMember. Mana deklarasi yang bener?

Jawab: pilihan 1. lockerCode = ID → String (nol depan aman), hoursUsed = jumlah jam → Integer, isMember = TRUE/FALSE → Boolean.

Tracing & Koreksi Bug 15 poin

Soal paling sering keluar — dan paling gampang dicurangi
Contoh soal Pseudocode di bawah punya 2 kesalahan. Trace pakai input 20, 24, 26, 30, lalu perbaiki. 
04 SET total = 0
05 SET count = 1
06 WHILE count < 4 DO
07     INPUT temperature
08     SET total = temperature
09     SET count = count + 1
10 END WHILE
11 DISPLAY total / 4
Cara ngerjain
1
Bikin tabel dulu, jangan ngitung di kepala. Kolom: baris · aksi/kondisi · count · temperature · total · output.
2
Isi nilai awal. Baris SET sebelum loop wajib masuk tabel (total=0, count=1).
3
Evaluasi kondisi dulu, baru isi angka. 1 < 4 → TRUE. Kalau FALSE, loop berhenti dan lanjut ke baris setelah END WHILE.
4
Satu baris satu langkah. INPUT, SET, increment dipisah — jangan digabung, itu yang bikin salah hitung.
5
Cek jumlah putaran. count < 4 mulai dari 1 → cuma 3 putaran (1, 2, 3). Input ke-4 nggak kepakai.
6
Lihat SET yang aneh. total = temperature menimpa, bukan menambah. Bandingin dengan pola total = total + x.
7
Tulis versi perbaikan utuh — bukan cuma "ganti < jadi <=". Dua bug: batas loop + akumulator.
Jawaban model
Trace program ASLI:  count 1,2,3 → total ketimpa 20, 24, 26
                     kondisi 4 < 4 = FALSE → stop
                     DISPLAY 26 / 4 = 6.5

Perbaikan:
WHILE count <= 4 DO
    INPUT temperature
    SET total = total + temperature
    SET count = count + 1
END WHILE
DISPLAY total / 4        →  (20+24+26+30)/4 = 25
Jebakan: kalau lu trace pakai program yang SUDAH benar, nilainya beda (25 vs 6.5). Soal minta trace program asli dulu — itu yang dinilai.
Sekarang lu coba · soal 2

Program ini masih salah. Input 10, 12, 14, 16, 18. Berapa output yang keluar?

04 SET total = 0
05 SET count = 1
06 WHILE count < 5 DO
07     INPUT temperature
08     SET total = temperature
09     SET count = count + 1
10 END WHILE
11 DISPLAY total / 5
Jawab: 3.2. count < 5 dari 1 → putaran 1,2,3,4 (input 18 nggak kepakai). Karena total = temperature, total berakhir 16, bukan 70. Output = 16 / 5 = 3.2.

Keputusan Boolean 15 poin

Kombinasi AND / OR / NOT + pilih IF atau CASE
Contoh soal Akses lab: cardValid AND (isStaff OR trainingDone) AND NOT isRestricted → ALLOW / DENY. Empat kasus harus dievaluasi satu-satu.
Cara ngerjain
1
Bikin tabel per kasus. Kolom: cardValid · isStaff · trainingDone · isRestricted · (staff OR trained) · NOT restricted · output.
2
Kurung dulu. (isStaff OR trainingDone) dihitung terpisah → simpan hasilnya T/F.
3
NOT dibalik. NOT isRestricted kalau isRestricted=TRUE → hasilnya FALSE.
4
AND = semua harus TRUE. Satu FALSE, hasil akhir FALSE → DENY.
5
Tulis output per kasus (i) ALLOW (ii) DENY (iii) DENY (iv) ALLOW, baru simpulkan.
6
IF/ELSE vs CASE: hasilnya cuma 2 kemungkinan → IF/ELSE cukup. CASE dipakai kalau milih dari banyak kategori (menu).
Jawaban model
IF cardValid AND (isStaff OR trainingDone) AND NOT isRestricted THEN
    DISPLAY "ALLOW"
ELSE
    DISPLAY "DENY"
END IF
Alasan wajib ditulis: "(ii) DENY karena isRestricted TRUE, jadi NOT-nya FALSE — walaupun card valid dan sudah training."
Sekarang lu coba · soal 3

cardValid = TRUE, isStaff = FALSE, trainingDone = TRUE, isRestricted = TRUE. Output-nya?

Jawab: DENY. (FALSE OR TRUE) = TRUE, tapi NOT TRUE = FALSE → satu komponen FALSE bikin AND FALSE.

Konstanta, Parameter, Validasi 15 poin

Format fungsi dosen + jangan pernah tampilkan nilai invalid
Contoh soal Rental sepeda: HOURLY_RATE konstanta, fungsi CalculateRentalFee(hoursRented), Main minta input durasi dan tampilkan biaya.
Cara ngerjain
1
Pisah angka aturan dari data. Tarif per jam = aturan → DECLARE GLOBAL CONSTANT Integer HOURLY_RATE = 12000.
2
Header fungsi: FUNCTION <ReturnType> Nama(<Type> param). Return type di DEPAN, tanpa kata RETURNS di belakang.
3
Bedakan dua istilah: formal parameter = nama di header (hoursRented), actual argument = yang dikirim saat dipanggil (duration).
4
Validasi di dua tempat. Fungsi nolak input aneh (RETURN -1), Main minta ulang pakai WHILE sampai valid.
5
Jangan DISPLAY hasil invalid. Cek nilai balik dulu, baru tampilkan.
Jawaban model
DECLARE GLOBAL CONSTANT Integer HOURLY_RATE = 12000

FUNCTION Real CalculateRentalFee(Integer hoursRented)
    IF hoursRented <= 0 THEN
        RETURN -1
    END IF
    RETURN hoursRented * HOURLY_RATE
END FUNCTION

MODULE Main()
    DECLARE Integer duration
    DECLARE Real fee
    INPUT duration
    WHILE duration <= 0 DO
        DISPLAY "Hours must be positive"
        INPUT duration
    END WHILE
    SET fee = CalculateRentalFee(duration)
    DISPLAY fee
END MODULE
Salah format = poin hilang. FUNCTION CalculateRentalFee(Integer h) RETURNS Real itu gaya bahasa lain, bukan konvensi dosen.
Sekarang lu coba · soal 4

Mana header fungsi yang sesuai konvensi dosen (return type di depan, tanpa RETURNS)?

Jawab: pilihan 1. Pola: FUNCTION ReturnType Nama(Tipe parameter). Nama parameter di header = formal parameter.

Sentinel & Validasi 15 poin

Loop berhenti karena penanda, bukan karena jumlah
Contoh soal Input skor 1–5, ketik -1 untuk stop. Hitung rata-rata skor valid. Trace 5, 9, 3, -1.
Cara ngerjain
1
Input pertama di LUAR loop, lalu input lagi di akhir body loop. Kalau lupa, loop-nya infinite atau data terakhir kelewat.
2
Sentinel dicek di kondisi WHILE (WHILE score <> -1), bukan di dalam IF.
3
Validasi range di dalam loop. 9 → di luar 1–5 → tampil "Invalid score", jangan masuk total/count.
4
Sentinel tidak dihitung sebagai data. -1 cuma penanda stop.
5
Cek count > 0 sebelum bagi. Kalau semua input invalid, bagi nol = error.
Jawaban model
SET total = 0
SET count = 0
INPUT score
WHILE score <> -1 DO
    IF score >= 1 AND score <= 5 THEN
        SET total = total + score
        SET count = count + 1
    ELSE
        DISPLAY "Invalid score"
    END IF
    INPUT score
END WHILE
IF count > 0 THEN
    DISPLAY total / count
ELSE
    DISPLAY "No scores"
END IF

Trace 5, 9, 3, -1 →  9 ditolak, total = 8, count = 2, output 4
Sekarang lu coba · soal 5

Input 4, 7, 2, -1 (valid 1–5). Berapa yang ditampilkan sebagai rata-rata?

Jawab: 3. 7 ditolak. total = 4 + 2 = 6, count = 2 → 6 / 2 = 3. Sentinel -1 tidak ikut dihitung.

Studi Kasus Gabungan 25 poin

Fungsi klasifikasi + modul utama (greenhouse)
Contoh soal Smart greenhouse. Zone A/B/C, humidity 0–100, sentinel -1. Klasifikasi: <40 DRY, ≤75 NORMAL, >75 HUMID. Kalau ada ≥2 DRY → CHECK IRRIGATION.
Cara ngerjain
1
Belah jadi dua bagian. (a) fungsi klasifikasi yang cuma balikin String, (b) MODULE Main yang urus input, validasi, hitung, output.
2
Tulis batasnya persis. < 40 DRY, <= 75 NORMAL, sisanya HUMID. Uji 39, 40, 75, 76 di kepala.
3
Validasi zone pakai WHILE sampai A/B/C — bukan IF sekali.
4
Validasi humidity 0–100, sentinel -1 keluar dari loop.
5
Akumulasi: count, total, dryCount. dryCount nambah kalau kategori = "DRY".
6
Rata-rata aman + aksi akhir (IF dryCount >= 2). Dua IF terpisah, jangan digabung.
Jawaban model (inti)
FUNCTION String classifyHumidity(Real value)
    IF value < 40 THEN
        RETURN "DRY"
    ELSE IF value <= 75 THEN
        RETURN "NORMAL"
    ELSE
        RETURN "HUMID"
    END IF
END FUNCTION

MODULE Main()
    ... validasi zone, loop sentinel, hitung count/total/dryCount ...
    IF count = 0 THEN DISPLAY "No readings"
    ELSE DISPLAY total / count
    IF dryCount >= 2 THEN DISPLAY "CHECK IRRIGATION"
    ELSE DISPLAY "CONTINUE MONITORING"
END MODULE

Zone B, input 35, 120, 38, 80, -1
→ 120 ditolak; count 3; dryCount 2; rata-rata 153/3 = 51; CHECK IRRIGATION
Pembagian poin: validasi zone 2 · loop/sentinel 2 · validasi range 2 · panggil fungsi 1 · hitung 2 · rata-rata aman 1 · aksi akhir 1.
Sekarang lu coba · soal 6

Pakai fungsi di atas: humidity = 75.5. Kategori apa yang dibalikin?

Jawab: HUMID. 75.5 nggak < 40, dan nggak <= 75 — jadi jatuh ke ELSE. Batas 75 itu punya NORMAL, di atasnya HUMID.

Value vs Reference soal bonus

Satu kata REF, hasil beda total
Contoh soal ChangeByValue(x) dan ChangeByReference(y), isinya sama-sama number = number + 5. x=10, y=20. Output-nya?
Cara ngerjain
1
Cari kata REF di header. Ada REF → by reference. Nggak ada → by value.
2
By value = salinan. Parameter dapat nilai 10, diubah jadi 15, tapi x di Main tetap 10.
3
REF = alias. Parameter menunjuk variabel asli, jadi y ikut jadi 25.
4
Tabel dua kolom: variabel Main (x, y) dan parameter (number). Jangan disatuin.
5
Urutan output = urutan eksekusi. 15 (dalam fungsi) → 10 (x) → 25 (dalam fungsi) → 25 (y).
Jawaban model
CALL ChangeByValue(x)      → number = 15 (salinan), DISPLAY 15
DISPLAY x                  → 10
CALL ChangeByReference(y)  → number = 25 (alias y), DISPLAY 25
DISPLAY y                  → 25

Output berurutan: 15, 10, 25, 25
Pembeda: baris 15 → MODULE ChangeByReference(Integer REF number)
Kalau dua parameter campur: Update(Integer p, Integer REF q) — p berubah cuma di dalam, q mengubah variabel asli.
Sekarang lu coba · soal 7

a = 4, b = 7. CALL Update(a, b) dengan Update(Integer p, Integer REF q): p = p * 2, q = q + p. Setelah balik ke Main, DISPLAY a, b keluar apa?

Jawab: 4, 15. Di dalam Update: p = 8, q = 7 + 8 = 15 (q alias b, jadi b ikut 15). Tapi p cuma salinan → a tetap 4.
