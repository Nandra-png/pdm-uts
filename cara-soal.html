Cara pakai halaman ini: tiap bab isinya sama urutannya.
  1. Soal asli — apa yang diminta di kertas ujian.

1

Spesifikasi & desain data

IPO, deklarasi, tipe data, test case · 15 poin

soal asli · Q1 Program reservasi pod. User mengetik memberID, jam mulai, dan jumlah pengunjung. Kalau pod masih kosong, program bikin kode konfirmasi.
  • (a) tulis IPO-nya
  • (b) deklarasi semua variabel + 2 assignment + jelasin kenapa memberID bukan Integer
  • (c) kasih 3 test case yang hasilnya beda-beda

1 Pisahin kalimat soal jadi 3 ember

Jangan ngarang IPO. Baca soalnya, tarik kata kuncinya. Tiga pemicu yang selalu dipakai:

kata di soalmasuk embercontoh dari soal ini
"user mengetik", "user memasukkan", "dibaca dari"INPUTmemberID, jam mulai, jumlah pengunjung, status pod
"validasi", "cek", "hitung", "bikin"PROCESScek 8 ≤ jam ≤ 19, cek 1 ≤ orang ≤ 3, cek pod kosong, bikin kode
"menampilkan", "muncul di layar", "pesan ke user"OUTPUTstatus diterima/ditolak, kode konfirmasi, jam mulai

Catatan: status pod itu input juga, walaupun user gak ngetik. Datanya datang dari sistem, bukan dari orang.

2 Tulis IPO-nya polos

Gak usah pakai kalimat panjang. Tiga baris, isinya variabel.

INPUT   : memberID, startHour, visitorCount, podAvailable
PROCESS : validasi 8 <= startHour <= 19
          validasi 1 <= visitorCount <= 3
          cek podAvailable
          buat reservationCode
OUTPUT  : confirmationMessage, reservationCode, startHour

3 Tentukan tipe data pakai tabel pemicu

Ini yang bikin nilai keluar. Hafalin 4 baris ini aja:

4 Baru tulis DECLARE + assignment

Urutan wajib: DECLARE Tipe nama. Assignment pakai SET nama = nilai.

01  DECLARE String memberID
02  DECLARE Integer startHour
03  DECLARE Integer visitorCount
04  DECLARE Boolean podAvailable
05  DECLARE String reservationCode
06  DECLARE String confirmationMessage
07  SET podAvailable = FALSE
08  SET confirmationMessage = "Pending"

Assignment itu nilai awal. Kenapa perlu? Biar variabelnya gak kosong waktu dipakai di IF. Kalau gak diisi, hasil ceknya gak bisa diprediksi.

5 Jawab "kenapa bukan Integer" pakai bukti, bukan alasan

Ini pertanyaan 1 poin yang paling sering dijawab ngambang. Bandingin dua baris ini:

"00123"  disimpan sebagai teks     -> 00123   (5 karakter, nol depan utuh)
 00123   disimpan sebagai Integer   ->   123   (3 digit, nol depan hilang)

Kesimpulan yang ditulis di kertas: memberID itu identifier, bukan kuantitas. Gak pernah dijumlah atau dikali. Kalau pakai Integer, nol di depan hilang dan ID-nya berubah jadi ID lain.

6 Test case: 3 baris, 3 cabang beda

Test case yang bener bukan "input bagus, input bagus, input bagus". Harus nyentuh cabang yang beda.

#inputyang diujihasil
1"00123", 10, 2, TRUEjalur normalConfirmed, R001
2"00123", 21, 2, TRUEjam di luar 8–19Rejected: invalid hour
3"00123", 11, 2, FALSEpod udah dipakaiRejected: pod unavailable
polanya Cari kata mengetik → INPUT. Cari kata menampilkan → OUTPUT. Sisanya PROCESS. Tipe data: teks→String, cacah→Integer, uang/desimal→Real, ya-tidak→Boolean. Test case minimal 1 normal + 1 invalid + 1 kondisi gagal.
latihan lu · bab 1baru, bukan dari dokumen

Mesin vending kampus. Mahasiswa mengetik studentID, productCode (misal "A1"), dan quantity. Program cek stok produk, cek saldo mahasiswa, hitung total harga, lalu menampilkan status berhasil/gagal, nama produk, dan sisa saldo.

Tulis: (a) IPO-nya, (b) deklarasi 6 variabel dengan tipe yang bener, (c) 3 test case.

          balance = balance - totalPrice

(b) deklarasi

(c) test case
1. "3001", "A1", 2   -> stok cukup, saldo cukup -> Berhasil, sisa saldo
2. "3001", "A1", 99  -> stok kurang           -> Gagal: stok habis
3. "3001", "A1", 2   -> saldo kurang          -> Gagal: saldo tidak cukup

Yang dinilai di ujian: tipe data harus pas (saldo = Real, quantity = Integer), dan tiap test case harus jatuh di cabang yang beda. Tiga kasus "berhasil" cuma dapet 1 poin.

Tracing loop + cari bug

soal paling sering keluar, dan paling sering salah

soal asli · Q2 Program ini harusnya baca empat suhu lalu tampilkan rata-ratanya. Tapi ada dua kesalahan di dalamnya.
  • (a) trace program aslinya, outputnya apa
  • (b) sebutin dua errornya + tulis versi yang bener

3 Tiga pertanyaan diagnosis — ini inti bab ini

Kalau lu cuma ngafalin "outputnya 6.5", lu bakal mati di soal lain. Yang harus lu bawa pulang itu cara nemuin bug. Tiga pertanyaan, urutannya selalu sama:

Pertanyaan ke-3 itu yang paling sering nyelametin. Rata-rata dari angka 20-an gak mungkin 6.5. Kalau hasil akhirnya aneh, berarti cara ngitungnya rusak, bukan datanya.

4 Perbaiki: dua baris doang

Bug-nya cuma di dua baris. Bandingin:

SALAH                                  BENER
06  WHILE count < 4 DO                  06  WHILE count <= 4 DO
08  SET total = temperature             08  SET total = total + temperature

Kenapa? count mulai dari 1, jadi count < 4 cuma ngasih 1, 2, 3. Mau empat kali, batasnya harus <= 4. Dan total = temperature itu nimpa — nilai lama dibuang. Yang numpuk itu total = total + temperature.

5 Trace ulang versi bener (wajib, buat bukti)

6 Versi FOR (jawaban poin (c))

SET total = 0
FOR count = 1 TO 4 DO
    INPUT temperature
    SET total = total + temperature
END FOR
DISPLAY total / 4

Lebih pendek, dan hitungan putarannya otomatis bener. Tapi kalau soal minta WHILE, ya jawab WHILE — jangan ganti bentuk sendiri.

jebakan yang bikin nilai 0 Jangan pernah nulis "outputnya 6.5 karena 26 dibagi 4" tanpa tabel. Yang dinilai itu tabel trace-nya (6 poin), bukan angka akhirnya. Angka doang = 1 poin.
polanya Dua bug klasik di soal loop: (1) count < n padahal harusnya count <= n — kurang satu putaran. (2) total = x padahal harusnya total = total + x — nimpa, bukan numpuk. Cek pakai 3 pertanyaan: jumlah putaran, nilai akhir, masuk akal gak.

3

Boolean & struktur IF

kombinasi AND / OR / NOT, dan kenapa kurung menentukan segalanya

soal asli · Q3 Akses ruangan: kartu valid, orangnya staff atau udah training, dan ruangan gak sedang dikunci.
  • (a) tentuin ALLOW / DENY buat 4 kasus
  • (b) tulis ekspresi boolean-nya (pakai kurung)
  • (c) tulis IF/ELSE-nya, dan apakah wajib pakai CASE?

1 Pecah ekspresi panjang jadi potongan kecil

Jangan evaluasi 4 variabel sekaligus. Bikin kolom antara buat tiap potongan:

cardValid AND (isStaff OR trainingDone) AND NOT isRestricted
                └────── potongan A ──────┘      └── potongan B ──┘

Potongan A = "staff atau udah training". Potongan B = "ruangan gak dikunci". Baru hasil akhirnya: kartu valid AND A AND B.

2 Isi tabel kasusnya

Ini yang dikumpulin di kertas. Perhatiin dua kolom tengah — itu jembatan biar gak salah:

kasuscardValidisStafftrainingDoneisRestrictedA: staff OR trainedB: NOT restrictedoutput
iTTFFTTALLOW
iiTFTTTFDENY
iiiFTTFTTDENY
ivTFTFTTALLOW

Kasus iii itu jebakan favorit: staff, udah training, ruangan kebuka — tapi kartunya gak valid. Satu FALSE di rangkaian AND langsung bikin semuanya FALSE.

3 Kenapa kurung penting (ini poin (b), 4 poin)

Tanpa kurung, komputer ngikutin urutan: NOT dulu, terus AND, terakhir OR. Jadi artinya berubah. Buktiin pakai kasus ii:

tanpa kurung:
cardValid AND isStaff OR trainingDone AND NOT isRestricted
  T    AND    F    OR     T     AND  (NOT T)
       F          OR           T AND F
       F          OR              F      -> hmm, ikut urutan AND dulu:

  (T AND F) OR (T AND NOT T)
      F     OR      F        = FALSE  -> DENY

dengan kurung:
T AND (F OR T) AND NOT T
T AND    T     AND   F       = FALSE  -> DENY

Nah di kasus ii hasilnya kebetulan sama. Yang bikin beda itu kasus lain — coba cardValid=T, isStaff=F, trainingDone=T, isRestricted=T di dua versi yang beda susunannya:

versihitunganhasil
cardValid AND isStaff OR trainingDone AND NOT isRestricted(T AND F) OR (T AND F) = F OR FDENY
cardValid AND (isStaff OR trainingDone) AND NOT isRestrictedT AND (F OR T) AND F = T AND T AND FDENY

Yang bener-bener beda: cardValid=T, isStaff=F, trainingDone=T, isRestricted=F.

versihitunganhasil
tanpa kurung(T AND F) OR (T AND T) = F OR TALLOW ← salah, dia bukan staff
dengan kurungT AND (F OR T) AND T = T AND T AND TALLOW ← bener, dia udah training

Intinya: selalu tandai kurung di ekspresi campuran AND + OR. Kalau lu tulis tanpa kurung, lu nebak-nebakan, dan yang dinilai cuma 1 dari 4 poin.

4 Tulis IF/ELSE-nya

IF cardValid AND (isStaff OR trainingDone) AND NOT isRestricted THEN
    DISPLAY "ALLOW"
ELSE
    DISPLAY "DENY"
END IF

Satu blok doang. Gak usah ada ELSE IF, karena hasilnya cuma dua: boleh atau gak.

5 Kapan CASE, kapan IF (jawaban poin (c))

Ini pertanyaan konsep. Aturannya simpel:

pakaikalau yang dipilih...contoh
CASEsatu nilai dari beberapa kategorizone = "A" / "B" / "C"
IFkombinasi beberapa boolean (AND/OR/NOT)cardValid AND (isStaff OR trainingDone)

Jadi jawabannya: CASE gak wajib di sini, karena aksesnya ditentuin kombinasi boolean, bukan milih satu kategori. Kalau soalnya nanya zona A/B/C, baru CASE yang pas.

polanya Ekspresi campuran → kasih kurung, jangan andelin urutan operator. Buat tabel kasus dengan kolom antara per potongan ekspresi. Satu FALSE di rangkaian AND = hasil akhir FALSE. Satu TRUE di rangkaian OR = hasil akhir TRUE.
latihan lu · bab 32 kasus, tulis ALLOW atau DENY

Akses lab komputer. Aturannya: boleh masuk kalau (mahasiswa terdaftar DAN udah bayar) ATAU asisten lab, dan labnya lagi buka.

Ekspresinya: ((isEnrolled AND hasPaid) OR isAssistant) AND isLabOpen

kasus 1 — isEnrolled=F, hasPaid=T, isAssistant=T, isLabOpen=T
kasus 2 — isEnrolled=T, hasPaid=T, isAssistant=F, isLabOpen=F
cara ngerjain
kasus(enrolled AND paid)OR assistantAND labOpenhasil
1F AND T = FF OR T = TT AND T = TALLOW
2T AND T = TT OR F = TT AND F = FDENY

Kasus 1 ALLOW — dia asisten, jadi syarat "terdaftar dan bayar" dilewatin. Kasus 2 DENY — semua syarat pribadi terpenuhi, tapi labnya tutup.

Perhatiin: isAssistant itu jalur alternatif, makanya dia ada di dalam kurung yang sama dengan isEnrolled AND hasPaid. Kalau lu tulis isEnrolled AND (hasPaid OR isAssistant), artinya beda total — asisten yang gak terdaftar jadi ditolak.

4

Konstanta, fungsi & parameter

bedain 4 makhluk yang mirip: konstanta, variabel lokal, parameter, argumen

soal asli · Q4 Sewa sepeda. HOURLY_RATE = 12000 dipakai semua kios, gak pernah berubah.
  • (a) sebutin mana konstanta, mana parameter, mana variabel lokal
  • (b) tulis header fungsi + tandain parameter formal, argumen aktual, return value
  • (c) tulis fungsi lengkap + Main yang validasi inputnya

1 Empat istilah, satu per satu

Ini bagian yang paling sering ketuker. Baca tabel ini pelan-pelan, satu baris satu baris:

istilaharti sehari-haridi kode ini
konstanta globalnilai yang dipakai bareng-bareng dan gak boleh berubahHOURLY_RATE = 12000
variabel lokalwadah yang cuma hidup di dalam satu modulduration, fee (di Main)
parameter formalnama slot yang ditulis di header fungsi — baru ada isinya kalau dipanggilhoursRented
argumen aktualnilai yang beneran dikirim waktu manggilduration di CalculateRentalFee(duration)

Analogi: parameter itu gelas kosong yang udah disiapin di meja. Argumen itu air yang lu tuang ke gelas itu.

2 Bedah header fungsi jadi 4 potong

Konvensi kelas: tipe kembalian nempel di depan nama fungsi, dan gak ada kata RETURNS di ujung.

FUNCTION   Real   CalculateRentalFee   (Integer hoursRented)
   │         │            │                    │
   │         │            │                    └─ parameter formal
   │         │            └─ nama fungsi
   │         └─ tipe nilai yang dikembalikan (RETURN)
   └─ kata kunci

Kalau lu nulis FUNCTION CalculateRentalFee(Integer hoursRented) RETURNS Real, itu gaya bahasa lain, bukan konvensi kelas ini. Salah format = poin hilang walau logikanya bener.

3 Trace satu pemanggilan

Durasi 3 jam. Ikutin alurnya:

Main: duration = 3→ CalculateRentalFee: hoursRented = 3→ RETURN 3 × 12000→ Main: fee = 36000

4 Kenapa return -1, bukan 0

Fungsi ini punya dua jalur keluar:

FUNCTION Real CalculateRentalFee(Integer hoursRented)
    IF hoursRented <= 0 THEN
        RETURN -1                    <-- tanda "input gak masuk akal"
    END IF
    RETURN hoursRented * HOURLY_RATE <-- jalur normal
END FUNCTION

0 itu jawaban yang sah (0 jam = 0 rupiah). Jadi 0 gak bisa dipakai buat nandain error. -1 itu mustahil secara bisnis, makanya aman dipakai sebagai penanda.

Tapi penanda doang gak cukup. Main wajib ngecek dulu sebelum nampilin:

MODULE Main()
    DECLARE Integer duration
    DECLARE Real fee
    INPUT duration
    WHILE duration <= 0 DO
        DISPLAY "Hours must be positive"
        INPUT duration
    END WHILE
    SET fee = CalculateRentalFee(duration)
    DISPLAY fee
END MODULE

Loop validasi itu gunanya: user gak bisa lanjut sebelum ngasih jam yang bener. Jadi -1 gak pernah nyampe ke layar.

polanya Header selalu FUNCTION TipeKembalian NamaFungsi(Tipe parameter). Parameter = slot di header, argumen = nilai yang dikirim. Nilai error pakai angka yang gak mungkin jadi jawaban sah (misal -1), dan pemanggilnya wajib ngecek.
latihan lu · bab 4fungsi baru

Kurir kampus. Ongkir dihitung kg × RATE_PER_KG dengan RATE_PER_KG = 9000 (konstanta global). Kalau berat yang dikirim ≤ 0, fungsi harus ngembaliin -1.

Fungsi: CalculateShippingFee(Integer kg), ngembaliin Real.

(a) output CalculateShippingFee(4)
(b) output CalculateShippingFee(0)
(c) di sini yang disebut parameter formal itu variabel apa?
cara ngerjain 
DECLARE GLOBAL CONSTANT Integer RATE_PER_KG = 9000

FUNCTION Real CalculateShippingFee(Integer kg)
    IF kg <= 0 THEN
        RETURN -1
    END IF
    RETURN kg * RATE_PER_KG
END FUNCTION

MODULE Main()
    DECLARE Integer weight
    DECLARE Real fee
    INPUT weight
    WHILE weight <= 0 DO
        DISPLAY "Weight must be positive"
        INPUT weight
    END WHILE
    SET fee = CalculateShippingFee(weight)
    DISPLAY fee
END MODULE

(a) 4 × 9000 = 36000. (b) -1, karena 0 ≤ 0 jadi masuk jalur error — bukan 0 rupiah.

(c) kg. Dia ditulis di header fungsi, jadi dia parameter formal. Kalau nanti Main manggil CalculateShippingFee(weight), maka weight itu argumen aktual.

Jebakan: kalau lu jawab (b) = 0, artinya lu belum paham kenapa 0 gak bisa jadi penanda error. 0 itu ongkir yang sah buat berat 0 kg.

5

Sentinel & validasi input

loop yang berhenti karena nilai penanda, bukan karena hitungan

soal asli · Q5 Survei kepuasan. Skor yang sah 1–5. Nilai -1 dipakai buat nyetop input.
  • (a) tulis loop sentinel-nya
  • (b) tulis lengkap: validasi + hitung rata-rata + jaga pembagian nol
  • (c) trace input 5, 9, 3, -1 → outputnya apa

1 Apa itu sentinel

Sentinel = nilai penanda berhenti. Dia bukan data, dia cuma lampu merah. Analoginya: antrian loket yang ditutup pakai papan "TUTUP" — papannya bukan pelanggan, jadi gak dihitung.

Di soal ini sentinel-nya -1, karena skor sah cuma 1–5. Angka negatif mustahil jadi jawaban, makanya aman dipakai sebagai penanda.

2 Pola loop sentinel: 4 bagian, urutannya wajib

Ini kerangka yang dipakai di semua soal sentinel. Hafalin bentuknya, bukan angkanya:

INPUT score                     <-- (1) baca SEKALI di luar loop
WHILE score <> -1 DO            <-- (2) selama bukan sentinel
    IF score >= 1 AND score <= 5 THEN
        SET total = total + score
        SET count = count + 1
    ELSE
        DISPLAY "Invalid score"
    END IF
    INPUT score                 <-- (3) baca LAGI di dalam loop
END WHILE
IF count > 0 THEN               <-- (4) jaga pembagian nol
    DISPLAY total / count
ELSE
    DISPLAY "No scores"
END IF

Kenapa input-nya dua kali? Karena kondisi WHILE dicek sebelum masuk. Kalau input cuma di dalam loop, kondisi pertama gak punya nilai buat dibandingin. Kalau input cuma di luar, loop-nya jalan terus tanpa henti (infinite loop).

3 Validasi range: pakai AND, bukan OR

Ini kesalahan nomor satu. Bandingin:

BENER : IF score >= 1 AND score <= 5 THEN    <-- di antara 1 dan 5
SALAH : IF score >= 1 OR  score <= 5 THEN    <-- hampir semua angka lolos

Kenapa OR salah? Angka 9: 9 >= 1 TRUE, jadi seluruh OR langsung TRUE. Angka -50 juga lolos. Range selalu pakai AND, karena dua syaratnya harus terpenuhi bersamaan.

5 Kenapa harus ada IF count > 0

Bayangin user langsung ngetik -1. Loop gak jalan sama sekali, jadi count = 0. Terus total / count = 8 dibagi 0. Program error (crash), bukan nampilin angka.

Jadi penjaganya bukan basa-basi: IF count > 0 itu yang nentuin program selamat atau mati.

tiga kesalahan yang bikin poin hilang 1. Sentinel ikut dijumlah. 2. INPUT cuma sekali (di luar atau di dalam loop doang) → infinite loop atau loop gak jalan. 3. Range pakai OR. Tiga-tiganya kelihatan sepele, tiga-tiganya bikin jawaban salah total.

Studi kasus greenhouse

soal gabungan: fungsi klasifikasi + sentinel + validasi + ringkasan, 25 poin

soal asli · Q6 Sistem greenhouse. Input zoneCode (A/B/C) dan reading kelembaban 0–100; -1 buat berhenti.
  • (a) tentuin input, output, validasi, aturan
  • (b) tulis fungsi klasifikasi dengan ambang 40 dan 75
  • (c) tulis Main lengkap (validasi zona, loop, rata-rata aman, aksi akhir)
  • (d) trace zone B dengan bacaan 35, 120, 38, 80, -1

1 Ubah aturan jadi garis bilangan

2 Tulis fungsinya

FUNCTION String classifyHumidity(Real value)
    IF value < 40 THEN
        RETURN "DRY"
    ELSE IF value <= 75 THEN
        RETURN "NORMAL"
    ELSE
        RETURN "HUMID"
    END IF
END FUNCTION

Perhatiin tandanya: < 40 (bukan <=) dan <= 75 (bukan <). Dua tanda ini yang nentuin 40 masuk DRY atau NORMAL. Di soal ini 40 harus NORMAL.

3 Susun Main jadi 5 blok

Kode lengkapnya 40 baris, dan gampang bikin panik. Padahal isinya cuma 5 blok yang ditumpuk:

blokisipoin
1 deklarasi + inisialisasizone, humidity, category, count, dryCount, total — semuanya di-set 0 dulu—
2 validasi zonaloop sampai zone-nya A, B, atau C2
3 loop bacaansentinel -1 + validasi 0–100 + panggil fungsi + update count/total/dryCount7
4 ringkasantampilkan zone & count, rata-rata aman (jaga count = 0)3
5 aksi akhirdryCount >= 2 → CHECK IRRIGATION, selain itu CONTINUE MONITORING1

Blok 2 dan 3 itu dua loop terpisah, jangan digabung. Zona divalidasi dulu sampai bener, baru bacaan diproses.

MODULE Main()
    DECLARE String zone
    DECLARE Real humidity
    DECLARE String category
    DECLARE Integer count
    DECLARE Integer dryCount
    DECLARE Real total
    SET count = 0
    SET dryCount = 0
    SET total = 0

    INPUT zone                                   <-- blok 2: validasi zona
    WHILE zone <> "A" AND zone <> "B" AND zone <> "C" DO
        DISPLAY "Invalid zone"
        INPUT zone
    END WHILE

    INPUT humidity                               <-- blok 3: loop bacaan
    WHILE humidity <> -1 DO
        IF humidity < 0 OR humidity > 100 THEN
            DISPLAY "Invalid humidity"
        ELSE
            SET category = classifyHumidity(humidity)
            DISPLAY category
            SET count = count + 1
            SET total = total + humidity
            IF category = "DRY" THEN
                SET dryCount = dryCount + 1
            END IF
        END IF
        INPUT humidity
    END WHILE

    DISPLAY zone, count                          <-- blok 4: ringkasan
    IF count = 0 THEN
        DISPLAY "No readings"
    ELSE
        DISPLAY total / count
    END IF

    IF dryCount >= 2 THEN                        <-- blok 5: aksi
        DISPLAY "CHECK IRRIGATION"
    ELSE
        DISPLAY "CONTINUE MONITORING"
    END IF
END MODULE

Perhatiin urutan di dalam ELSE: panggil fungsi → DISPLAY kategori → baru tambah count dan total. Kalau DISPLAY-nya ditaruh di luar IF validasi, angka 120 bakal ikut kecetak sebagai kategori padahal ditolak.

Parameter by value vs REF

soal tambahan — yang nentuin variabel di Main berubah atau nggak

soal asli · Q7 (latihan tambahan) Dua submodul: satu nerima parameter biasa, satu nerima parameter REF.
  • tentuin 4 output sesuai urutan eksekusi
  • lengkapi trace table
  • jelasin kenapa x gak berubah tapi y berubah

1 Analoginya dulu

modeanalogiefeknya
by value (tanpa REF)lu dikasih fotokopi dokumen. Lu corat-coret fotokopinya.dokumen asli di Main utuh
by reference (pakai REF)lu dikasih remote yang sama dengan TV di ruang tamu.TV-nya ikut berubah

Jadi pertanyaan "variabel di Main berubah gak?" jawabannya cuma satu: ada REF di header atau nggak.

2 Cara ngenalin di kode

MODULE ChangeByValue(Integer number)          <-- gak ada REF: salinan
MODULE ChangeByReference(Integer REF number)  <-- ada REF: nempel ke variabel asli

Bedanya cuma satu kata. Tapi efeknya besar: di versi REF, number itu nama lain buat variabel di Main. Ubah number, ubah juga variabel aslinya.
